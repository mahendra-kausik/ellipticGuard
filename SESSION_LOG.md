### Layer 8 subpart split (recorded per CLAUDE.md's "split a too-big layer into logical subparts" rule)

Layer 8 is three separable pieces with different risk profiles, so it splits cleanly. The full-layer gate applies at the end of 8c only.

- **8a — core module + tests (data-free).** `src/models/gnn.py` (per-time-step snapshot builder, sparse adjacency normalization, GCN / GraphSAGE / EvolveGCN, masked training loop, an `evaluate()`-interface adapter) + `tests/test_gnn.py` (4 synthetic tests, opening with `pytest.importorskip("torch")` so lean CI stays green without torch). No training run. *Why first:* it's the only part with real correctness risk (hand-rolled sparse tensor math), and it's testable without touching data.
- **8b — pipeline + the real run.** `pipelines/train_gnn.py` (DVC stage, mirrors `train_advanced.py`), `params.yaml` `gnn:` section, `dvc.yaml` `train_gnn` stage. Trains all three over N seeds on steps 1–29, early-stops on 30–34, evaluates once on 35–49. Logs three MLflow runs, **registers nothing** (comparison models, not serving candidates — the same call Layer 6 made for the calibrated model). Writes `gnn_metrics.json` + `gnn_per_time_step.csv`. *Why separate:* this is the slow part (CPU training × 3 models × N seeds) and it can't start until 8a's math is trusted.
- **8c — docs + gate.** `PROJECT_PLAN.md` §4/§6 amendments, D-030, README results rows, SESSION_LOG changelog, commit+push, gate.

**Reasoning for the split:** 8a's tests are the thing that makes 8b's numbers believable — a hand-rolled GCN that silently normalizes the adjacency wrong still trains and still produces a plausible-looking F1. Getting the math under test *before* spending CPU on a run, and before writing any number into a comparison table, is the difference between a measured result and a coincidence.
